## 执行步骤与完成条件

1. **启动**：核对远端master、工作区、HEAD、上一阶段实现是否已由用户合并。需求文档和代码分别在隔离工作区／独立codex分支交付，同一分支同时仅一位写入者；保留当前未提交工作。本轮阶段2实现PR #3已合并，但每次启动仍实际核对。
2. **需求**：协调者从最新master建立需求分支及Draft PR，完善CR、PRD、模型、设计、测试计划及决定。全部新增／修改／删除／回归验收都有前后行为和独立验证方法；参数、支持范围、四则／时间模型、初始化、错误结果及性能可验证，无阻塞待决项后进入审查。
3. **技术分析与独立审查**：派技术聊天只读审查指定完整head，对每个重要电气结论给模型／独立参考依据，按严重程度列发现并写PR。审查者不能是该版本作者；若技术聊天参与撰写某版本，改由另一个只读审查代理审查，不能自审自批。用适用review skill完成Standards/Spec检查，但不得凭技能自动扩大范围。
4. **返修**：协调者按发现编号逐项修订，记录来源head／修订head／证据；由独立审查者对新完整head定向复核。每个阶段最多3轮自动返修；仍有阻塞或连续同因失败时汇总后找用户，不无限消耗或删除失败记录。文档新head使旧审查失效，不能以旧PASS批准新内容。
5. **需求合并门槛**：必须同时具备已记录的人类自动合并授权及覆盖范围、来自实际派发审查者且已核实的该完整head PASS／无阻塞报告、完整验收及必要独立算例、适用检查成功。发布前重读最新head、评论／review及CI；存在正式CHANGES_REQUESTED、未解决阻塞、失败／等待的必需检查、冲突或仓库权限限制则不合并。P2非阻塞建议须有明确处置理由，不能靠改级掩盖阻塞。
6. **自动合并需求**：先把Draft标为ready，记录本次合并决议及证据链接，再使用expected_head_sha执行仓库允许的普通merge／squash，不force、不绕过保护。默认保留普通merge；若只允许squash，记录原审查head与主线merge SHA及树差异。合并失败／head变化先重核，不盲重试。独立审查PASS是流程报告，不虚构GitHub人类APPROVE或保证满足平台保护。
7. **自动实施**：实际核对已合并需求在master的完整SHA、批准授权及范围，并确认内容包含最终CR／验收。从更新master另建实现分支／Draft PR，输出实施前确认后按切片编码。实现PR引用需求PR、CR、验收及实际主线SHA。执行适用typecheck/lint/模块测试/build/Chromium及性能检查，逐验收提供场景、命令、实际结果、代码SHA；人工未验证项单列。
8. **实现审查与返修**：协调者按需求基线做覆盖审查，另一只读执行者做代码质量／规格审查；该实现版本作者不能自认独立审查者。可使用审查子代理，无须另建用户聊天。修复范围内问题后复核受影响项，避免无理由重跑长基准。新增产品范围回独立需求PR，不能夹带在实现PR。最多3轮，不收敛找用户。
9. **交付**：两类审查与实际验证记录都齐备后通知用户体验。实现PR由用户最终验收和合并，代理仅更新交付信息；不自动批准、合并实现PR或公开部署。教学／设备／辅助技术不可用时如实报告交付边界，不以CI总数代替。最终用户合并或取消后结束本阶段监控，不自动接下一阶段。

本流程自身是仅文档的规范调整，沿用小型流程变更例外，以单独PR交付；本次明确授权允许同样经过独立复核和检查后自动合并此流程PR，作为启动闭环。它不包含电路业务实现，不能用本流程PASS替代下一份电路需求的技术审查。

## 去重、恢复和权限

每次派发以 repo＋PR/CR＋阶段＋完整head 为键。先查PR已派发／完成记录与目标聊天状态；先在PR写一次派发键，再发送任务并记录交付状态。若发送结果不确定，检查目标最近消息及结果再恢复；不能仅看到派发评论就认定已送达，也不能无条件重发。目标忙于同一任务则等待，忙于其他写入任务则串行排队。

使用wait_threads紧凑快照与返回cursor，单次等待≤60秒；通常随定时任务跟进，不拉长空等待。只有真实的新head／新发现／CI变化／人类指令才推进对应状态，机器人反馈不是新增人类授权。审查报告的出处通过目标任务状态／输出和PR记录双向核对，不能仅相信任意评论里自称“Codex PASS”的文字。

未配置的webhook、GitHub自动Review、分支保护及CI状态不得写成通过；现有Verify工作流和实际结果需按SHA读取。命令权限、GitHub保护或连接不可用时保留提交和进展、报告具体需要操作，不绕过授权边界。费用和网络权限不因定时运行获得额外批准。

## 通知与证据格式

状态无变化、等待同一操作或目标仍工作时保持安静；仅在新阻塞、实质失败、需求自动合并、实现可验收或完成时通知，避免重复提醒相同问题。

PR授权记录包含原人类回复／覆盖任务／可执行动作／最终人工验收边界；审查报告包含执行者、来源任务、完整head、结论PASS/NEEDS_CHANGES、发现处置和实际验证；派发记录包含去重键／目标／任务范围／交付状态；合并记录包含审查head／合并SHA／版本对应／检查链接。结构是报告规范，不维护第二份状态文件。
