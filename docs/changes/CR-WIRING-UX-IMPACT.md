## 1. 绘制与点击竞争

`src/editor/Breadboard.tsx`当前按导线、孔位命中、元件、已选导线端点柄的顺序绘制（基线约224–322行）。导线已有13单位透明命中带；之后的孔位半径9命中圆会截获经过其位置的线身点击。仅加宽线条不能解决层级竞争。元件组同时处理选择／拖动／运行开关和按钮按压，不能简单把所有导线无条件抬到最上层。

拟处理：按当前“查看连接／连线”模式决定孔位与导线线身的指针优先级；实际元件本体控制保持可用，显式引脚孔可在连线模式接线。已选导线的端点／曲线控制柄单独在交互顶层。键盘孔位观察和连接观察器表单作为鼠标被线身覆盖时的替代入口。

真实命中回归必须用Chromium坐标指针点击：对着线身且处于背景孔位中心的位置仍应选线；连线模式对同一位置应选孔。只用对SVG节点派发click的模块测试无法证明命中层已经正确。

## 2. 曲线几何与手势

现在线条和改接预览分别拼接横／竖折线字符串，所选线只有颜色和切换折线方向控件；线形字段是`Wire.bend`两值。需增加纯显示几何模块，由实际线条、透明命中带、高亮、创建／改接预览共同使用，避免多处公式偏离。

拟保留两个旧`bend`值并新增`curve`及必填`curveControl={x,y}`，只在v5接受。基线viewBox为880×650，控制点范围x∈[16,864]、y∈[16,634]；默认是端点中点加48倍法向量(-dy/L,dx/L)后夹紧。二次贝塞尔端点与控制点均在画布内，路径可保持在可见范围。几何字段不交给网络合并、求解器或SPICE。

需要为曲线柄增加独立临时拖动会话，保存起始几何／pointerId／文档版本，沿用现有坐标转换、捕获、拖动阈值与取消原则。拖动结束调用一次编辑命令；预览不写历史／存储。模式／选择／文档变化、线被删除或窗口失焦时取消，不能以旧快照覆盖新编辑。键盘每次有效按键提交一次，忽略repeat；Tab／Escape等既有行为不能被控制柄抢占。

端点改接保留控制点。控制点落在端点连线上合法；同端点、缺失／非有限／越界控制点非法。折线转曲线补默认点，转折线移除控制点，不保留不可见的旧参数。

## 3. 占用模型及所有入口一致性

`src/editor/model.ts:45–76`使用单一`occupied`集合：先记录所有元件脚，再拒绝任何插入这些孔的导线。`Breadboard`另将脚和线混合成“已占用”显示集合；`src/editor/components.test.ts`逐脚断言导线不能接入元件孔，改接测试也依赖旧规则。

拟拆为元件引脚与导线端点两类计数／集合，独立校验各自≤1；共同孔位允许一个引脚加一个线端。不要只在`wire`命令临时放行：放置、移动、旋转、改接、完整文档校验、保存／载入及编译预检必须得到同一结论。可用状态需按当前操作区分，不能将“仅元件引脚”错误标成连线不可用。

元件移动／删除已经不带走导线，继续保留；只释放移动前元件脚的占用。另一端／原孔位／其他对象不能顺带修改；非法编辑保持原对象和历史。

## 4. 存档与旧版保护

`readCircuitDocument`先校验／白名单复制，再规范化为v5；`storage.parseDocument`还会执行完整物理校验。编辑器接受而存储仍按单集合拒绝会导致内存作品无法保存，必须同步。

拟保持schema v5和现有存储键；通过`bend='curve'`的严格判别与`curveControl`校验扩展显示参数。v5已有折线不用新增字段。旧schema1–4在升级前按旧线形／单占用校验，明确拒绝曲线、曲线字段或当时不合法的共孔输入；不能先升到v5再意外放宽。既有v5作品保留值、身份、折线、模型版本、电源和容量，不自动改成曲线。

旧程序遇曲线会拒绝未知`bend`；旧程序遇元件＋导线共孔会在完整校验中拒绝，原有加载失败保护会保留存档。需求验收要求用固定基线读取器核实保护，不能仅根据本分析声称已运行证明。未知／缺字段／NaN／越界曲线继续保护原文；加载只读，下一次有效编辑才保存规范化文档。

## 5. 电气与教学影响

`circuit/network`只合并板内导体、显式wire.from/to及既有理想触点；元件脚也按同一孔位ID查网络，故共享该ID不需要新增电气模型。与接到同组空孔的网络、代表性LED／RC读数及已有振荡器SPICE网表应等价。曲率、颜色、线条交叉不允许成为隐式接点。

`PartControls.tsx`、`PartShape.tsx`、`src/tutor/components.ts`及USER_GUIDE中的“引脚孔已占用，请接其他空孔”表述需更新；明确这是虚拟共孔便利规则，真实面包板同组孔方案仍可读。说明查阅不触发编辑／求解，电位器、LED等引脚身份和极性不变。

## 结论

三项可以在现有显式网络和局部编辑命令上实现；主要成本在模式命中与存档／占用一致性。当前没有需新增器件或求解能力的阻塞。需求PR需确认本CR的一引脚＋一线范围、单控制点曲线及旧版保护；用户合并后才能实施。
