# 阶段2：固定性能基准与采样规程

2026-11-04，针对 [复核P2](https://github.com/bjstevenyang/ai-circuit-tutor/pull/2#issuecomment-6624787668) 的需求规格修订。本文是未来实施验收规程，尚无基准实现或测量结果。数值预算见 [CIRCUIT_MODEL](../CIRCUIT_MODEL.md)，阈值／环境见 [SYSTEM_DESIGN](../SYSTEM_DESIGN.md)。不增加产品功能、运行依赖或公开部署。

## 固定输入集

P/N分别是同一固定电源正／负端，X/Y/Z为逻辑网络，不是孔位ID。每次输入按下表恢复完整配置，禁止继承上次提示、结果、缓存、按压或动态状态；暖态测量可保留代码JIT但必须区分数据缓存命中／未命中。ID按表中序号稳定排序，数值用SI单位；最终实现PR需提交实际fixture文件、内容SHA256、真实孔位／导线及编译后P/T/候选／未知数数目。本轮不声称逻辑网表已过实际安装校验。

| 场景 | 固定网表／控制输入 | 测量操作及独立结果要求 |
| --- | --- | --- |
| B-RGB | [E2-RGB](CR-STAGE-2-EXPERIMENTS.md)，1RGB/3电阻330Ω/3开关，共7件 | 核心取三开关全闭合；UI从R关、G/B开切R为开，测电流／颜色按E2-RGB变化；每次样本后反向切换作清理准备，不计入样本 |
| B-NPN | E2-NPN修订网表，含Rb10k、R_down100k、R_ref100k及330Ω/LED/NPN/开关，共7件 | 核心与UI从断开切闭合；应由VC4.5 V／Ic0到VC.2 V／Ic7.012696970 mA，LED6.969696970 mA；下一次先断开恢复 |
| B-RC | E2-RC，C100μF、两R10k、两开关，共5件，充电开关闭合／放电断开 | 核心：每次先编译原网表，输入t=0、Vc=0、Δt=.05 s；UI在已运行、模拟t=5 s时断充电开关再闭放电开关（两个操作分开各记一组样本，观察连续性），不把t=0到5 s等待算作响应延迟 |
| B-PIEZO | E2-PIEZO，单压电和闭合开关，共2件，方波500 Hz | 核心求500 Hz稳态；UI从250切500 Hz，有许可音频；频率与Vpp按E2-PIEZO，清理准备改回250，不计样本 |
| B-MAX | 下文24件有效DC网表，4.5 V、2RGB、2NPN，P=6/T=2／576候选 | 核心取Rb均10k；UI将T1的Rb由100k改10k，其他不变，观察T1从受控到饱和；必须实际返回支持且KCL合格，不能把早退“不支持”计作性能通过 |
| B-OVER | 从B-MAX增加第25件1kΩ电阻接P–N，其他不变 | 核心直接输入非法文档必须预算／格式拒绝、无有限读数；UI尝试新增第25件被原子拒绝且作品仍24件，不能把原子拒绝当作已运行25件。另单测P/T预算超限见下文 |

B-MAX精确逻辑网表：

- RGB U1/U2：每只K→N，R/G/B分别经独立330Ω接P；2RGB＋6R，共8件。
- NPN T1/T2：E→N，B经10kΩ接P并经100kΩ接N，C经1kΩ接P；2NPN＋6R，共8件。基极驱动只有电阻网络；10k时Ib=.373 mA、Ic=4.3 mA、VCE=.2 V；100k时Ib=.031 mA、Ic=3.1 mA、VCE=1.4 V。没有截止LED浮置支路。
- 电阻分压支路D1–D4：各为P→1kΩ→Zi→1kΩ→N，四个Zi独立；共8R，各支路2.25 mA。
- 合计24件，P=6、T=2、最多576候选；基极／负载／分压均有有限参考。每个RGB各16.666666667 mA，两NPN每只源电流4.68 mA，四分压总9 mA，电源总51.693333333 mA。实际矩阵未知数由实现编译器报告，不冒称此网表能达到128维。

独立超限模型输入：B-MAX去掉D4的2R、增第3只RGB（K→N、R/G/B都经原U1对应电阻的输出网络并接）；共23件、P=9/T=2，必须在候选枚举前因RGB数量／展开支路预算拒绝，不能进入非唯一解枚举后才返回。该样例只考察超分析预算预检与作品可保存，不要求支持该网络。

矩阵128／129未知数门槛为编译层合成结构测试：报告输入支路表和维数计算，分别接受预算／预检拒绝；128维不要求一定能由24件板上器件产生。不得把不可达的合成矩阵说成浏览器正常搭建，也不要求用它代替B-MAX的真实UI性能。120/121线边界仍按既有物理与结构测试验收，不通过制造不合法孔位伪造有效120线作品。

## 时间测量

1. 按设计规定硬件和Chromium版本启动生产构建，单worker、固定视口1440×900，不开DevTools、不录屏／截图／trace；关闭其他测试并在前台聚焦。记录OS、CPU、内存、Playwright及浏览器完整版本、代码SHA、构建配置、fixture哈希。测试用本地fixture，不读取学生作品。
2. 核心编译＋求解：每场景预热10次再测100次；使用同一进程单调高精度时钟，t0紧邻调用编译前，t1在同次求解／校验／结果构造返回后。包括预算预检、网络构建及分析，不包括fixture解析、物理布局准备、React、存储、测试断言和UI调度。每次重新编译，不得只计缓存结果；B-RC包括等效网络建立和一次.05 s解析推进。
3. UI响应：每场景预热10次、测100次。t0为指定真实控件事件处理入口（键盘与指针分组，不能混合），t1为同一documentRevision/sessionId的期望状态提交后首个requestAnimationFrame读取到正确DOM／SVG状态；样本必须由状态断言匹配本次输入，不能只等固定时长。t0之前发送事件的工具／IPC耗时不计；模型计算、保存尝试、React提交及主线程排队在t0/t1之间的开销均计入。带声场景t1取视觉与音频结果应用标记两者较晚者；不以物理扬声器延迟评判。
4. 音频更新100 ms：B-PIEZO相同控件t0至频率／增益参数应用且100 ms内达到目标变化95%的音频时间戳；与UI 200 ms门槛分别报告。按原平滑增益时间常数，不能只记录发起setTarget调用。实际试听另验。
5. 停止响应：每个B-RGB/B-NPN/B-RC/B-PIEZO/B-MAX另做10次预热＋100次测量，从运行中停止按钮事件入口t0，到界面已停止且该会话振荡器均停止／断开、后续回调失效标记完成t1；取较晚者，不计人工听觉延迟。B-PIEZO声音许可开、音量50%，B-RC在t=5 s。重新运行是下次样本准备，不计入。
6. 后台暂停：B-RC在t=5 s进入后台，使用实际墙钟等待10 s，再前台聚焦；后台时间不计性能样本。记录暂停前后模拟时间，恢复首批至多新增.05 s；后台不得持续推进、发声或补算10 s。重复10次，逐次断言，不计算为普通UI P95。
7. 各场景／操作／指标分别输出100条原始ms样本，不混合模式、不删慢样本、不扣除计时开销。升序第ceil(.95×100)=95个值为P95；核心≤100 ms、UI≤200 ms、停止≤100 ms，另外音频≤100 ms。错误结果、取消、超时均计失败；环境中断整组作废重测并记录原因，不能只保留快样本。

这些标记是测试观测点，不要求向学生展示调试时间或额外产品控件。实际计时代码／性能runner在实现PR编写；此需求阶段不添加运行依赖，也不预先声称命令存在。未来基准入口可归于Chromium测试目录并在TEST_PLAN记录实际执行命令。

## 长运行与回收采样

单独启动Chromium，不与上述耗时测试混跑；使用同一固定环境，单标签、无trace／截图，音量50%，已明确许可音频。通过CDP [Performance.getMetrics](https://chromedevtools.github.io/devtools-protocol/tot/Performance/#method-getMetrics)取得JSHeapUsedSize，[HeapProfiler.collectGarbage](https://chromedevtools.github.io/devtools-protocol/tot/HeapProfiler/#method-collectGarbage)做受控回收；CDP是测量工具，不是产品依赖。权限／API不可用则标“内存未验证”，不以DOM对象数替代。

- **M-RC**：固定B-RC（充电开关闭合、放电断开），每个会话实际前台墙钟运行60 s；不快进测试时钟。会话自动到达模拟60 s则已停止；若因调度限额尚未到达，由测试在墙钟60 s点击停止，并记录实际模拟终点。每个会话后确认stopped、当前结果／提示／时钟引用清理，无旧回调继续更新。下一会话仅重新运行同一配置，不重新加载页面。
- **M-PIEZO**：固定B-PIEZO500 Hz、开关保持闭合、声音许可开；前台墙钟60 s后点击停止（周期模式没有RC的60 s自动时限）。每次确认振荡器停止并断开；停止间可保留一个会话AudioContext，不允许随运行次数增长。第10次采样后卸载工作台，验证Context关闭及监听／定时器释放。
- 两组分别新页面运行10个会话；每次停止完成后等待真实墙钟1 s，调用collectGarbage两次（间隔100 ms），第二次完成后等待100 ms，立即取JSHeapUsedSize。不能只写“等稳定后采样”或在采样前清空作品以改变负载。采样工具本身不保留结果对象／heap snapshot，原始指标写到测试进程。
- H1定义为第1个60 s会话结束按上述回收采样得到的值；H2–H10为后续同法采样。要求每个Hi−H1≤10,000,000字节（i=2…10），同时记录全部10点和负增长，不只看最后一点。独立报告每组定时器／振荡器／Context创建、存活、清理计数；采样后停止仍不能被旧回调恢复。
- M-RC与M-PIEZO都要通过；不能拿可控时钟跑满模拟60 s替代实际持续运行。若机器／工具不可用，如实列未验证项，由用户判断交付边界，不把文档校验当实测。
